The test of our prediction, now on all five cores. We enumerated every combination of base, index and displacement, with every extra value set to zero, so all five rows compute exactly the same rax. The pattern is a block: the three E-core columns take two cycles for the last two rows and one cycle everywhere else, and neither P-core ever takes two. Our first guess was that three parts are slow, but the index-plus-displacement row has only two parts and is still slow, so the rule is index and displacement together. Two cells need a word. Raptor Cove does base and base-plus-displacement in about a sixth of a cycle, because it resolves a small constant at rename before execution; Lion Cove does not do that for LEA, and there is a backup slide on it. The missing combinations are not oversights: index on its own cannot be encoded, because with no base x86 always adds a four-byte displacement, and a displacement on its own has no register input to form a chain.
