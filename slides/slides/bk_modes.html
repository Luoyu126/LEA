Prefixes and sizes keep the rule

The 0x67 prefix (32-bit address) and a 32-bit result still pay on Gracemont. A 16-bit result is slow for every form, which hides the +0 effect. * RIP-relative always has a disp32, so this compares disp 0 with 64 (throughput).

Backup, in case someone asks about other LEA forms. All of these were written byte by byte and checked with objdump. With the 0x67 prefix the address is computed in 32 bits, and a 32-bit result is also slow with a displacement, so the effect is about the address form, not the 64-bit adder width. A 16-bit destination is slow everywhere: 2 cycles on the P-core and about 3.6 on Gracemont, for every form, so the plus-zero effect disappears under it. RIP-relative LEA always carries a 4-byte displacement and reads no register, so we could only compare displacement 0 with 64, in throughput; the value makes no difference.
