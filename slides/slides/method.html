How we measured

01

Dependency chain

Each LEA feeds the next, so time ÷ count = latency. 200 unrolled, 200k loops, median of 7.

02

Exact bytes

Every encoding written byte by byte and checked with objdump. An assembler drops a +0.

03

One core at a time

Pinned with SetThreadAffinityMask. P, E and LP-E measured separately, two CPUs each.

04

Calibrated cycles

rdtsc divided by an add rax,rcx chain (1 cycle) timed right before and after.

3 / 12

This is how we tested the prediction. The four steps are in the order they happen, which is what the arrows mean. The chain means each instruction waits for the previous result, so we measure latency. We wrote the bytes by hand because an assembler silently removes a +0. Pinning matters because the three core types give different answers. The cycle count comes from the timestamp counter, calibrated against a known 1-cycle instruction, measured right next to each kernel so frequency changes cancel. Two things worth saying out loud but not on the slide: we ran natively on Windows rather than WSL, because WSL cannot pin to a core type and showed about twenty per cent noise against two per cent native; and we repeated everything on a second laptop, an i7-13700H, where the calibration held even though the clock differed by about thirty-five per cent between the battery and AC runs.
