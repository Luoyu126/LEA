How we measured

01

Dependency chain

Each LEA feeds the next, so time ÷ count = latency. 200 unrolled, 200k loops, median of 7.

02

Exact bytes

Every encoding written byte by byte and checked with objdump. An assembler drops a +0.

03

One core at a time

Pinned with SetThreadAffinityMask. P, E and LP-E measured separately, two CPUs each.

04

Calibrated cycles

rdtsc divided by an add rax,rcx chain (1 cycle) timed right before and after.

Native Windows, not WSL

WSL can’t pin to a core type and showed ±20% noise; native runs agree within ±2%.

This is how we tested the prediction. The four steps are in the order they happen. The chain means each instruction waits for the previous result, so we measure latency. We wrote the bytes by hand because an assembler silently removes a +0. Pinning matters because the three core types give different answers. The cycle count comes from the timestamp counter, calibrated against a known 1-cycle instruction.
